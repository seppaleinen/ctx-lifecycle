# ADR-001: Domain-Isolated Context Pools

**Date:** 2026-10-30
**Status:** Accepted (partially superseded by ADR-007)
**Deciders:** Wayfinder Map #2

> **Supersession note:** The original description of the Global pool as "immutable, never evicted" was revised by [ADR-007](ADR-007.md). The Global pool now has an LRU eviction ceiling via `pools.global.maxTokens`, with `critical` messages exempt from eviction. The Project pool (PoolID.PROJECT) was also added by ADR-007.

---

## Context

Current agent harnesses treat conversation context as a monotonically growing, append-only log. This leads to context degradation, poisoning from stale information, and unnecessary token expense over multi-hour sessions.

## Decision

Implement four isolated context pools with distinct eviction policies:

1. **Global Pool** (immutable, never evicted) — System invariants, types, schemas
2. **Planning Pool** (summarize before eviction) — Research, design, contracts
3. **Execution Pool** (discard oldest on overflow) — Active code changes, diffs
4. **Testing Pool** (discard on complete) — Test output, failures

Each pool has its own `ContextPool` object with `id` and `messages` array. The `ContextRouter` maintains all four pools in memory and combines them per active state.

## Consequences

- Maintains flat token ceiling (15k-25k) over long sessions
- Prevents stale-symbol hallucinations by isolating phase-specific context
- Improves Pass@1 success rate by keeping relevant context in scope
- Adds complexity to message routing via `ContextRouter.getActivePools()`
- Requires careful pool swap timing to avoid context loss
