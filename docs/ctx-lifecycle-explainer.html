🚀 ctx-lifecycle

Intelligent Context Management for OpenCode V2 — Managing conversation history across five context pools

🎯 First Half: The Basics

The Problem We Solve

⚠️ The Context Problem

When working with AI assistants over long sessions, conversation context keeps growing indefinitely. This leads to:

  • 💰 Wasted tokens: Old messages still count against your limit
  • 🔄 Stale information: Wrong context from earlier tasks
  • 🎯 Reduced precision: AI loses focus on current task

Our Solution: 5 Context Pools

🌍 Global

System knowledge (LRU-capped, never fully deleted)

📌 Project

Issue-scoped notes (cleared with /new-issue, LRU-capped)
⟶

📋 Planning

Research & design (key items retained, rest summarized then deleted)
⟶

⚡ Execution

Active coding (oldest evicted)
⟶

🧪 Testing

Test results (discarded when done)

Superseded, retraced content

Only if retention.evictSourcePool is on

🌟 Key Features

⚙️ Issue-Scoped Eviction

Context automatically cleaned up per issue/task - no manual management needed

📊 Flat Token Budget

Keeps token usage between 15k-25k over hours-long sessions

🎯 Better Accuracy

Prevents context "pollution" from outdated information

🧭 Clear Boundaries

Each phase has its own context - clean separation of concerns

🗑️ LRU Eviction

Global and Project pools are capped by token ceiling; least-recently-used messages are evicted first. Critical (pinned) messages are never evicted.

📌 Project-Scoped Context

A dedicated Project pool rides alongside Global on every state. Clear it with /new-issue when starting a fresh issue.

💻 Quick Commands

🧩 Core Components

state-machine.ts

Manages the 6-state transition matrix with validation. Throws TransitionError on invalid moves.

router.ts

Maintains all 5 pools in memory. Provides getActivePools() and addMessage() methods.

summary-generator.ts

Creates one-sentence summaries for handoff events between stages, plus deterministic retained-context extraction (acceptance, requirements, architecture, research).

types.ts

Core type definitions: ContextPool, ContextMessage, STATE_TO_POOL mapping.

📋 State Transition Matrix

From State To PLANNING To CODING To DEBUGGING To COMPLETE
PLANNING – (stay) ✅ Valid ❌ Invalid ❌ Invalid
CODING ❌ Invalid – (stay) ✅ Valid ✅ Valid
DEBUGGING ❌ Invalid ❌ Invalid – (stay) ✅ Valid
COMPLETE ✅ Valid ❌ Invalid ❌ Invalid – (stay)
