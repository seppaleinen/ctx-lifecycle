# ADR-004: Minimal Hand-off Summaries

**Date:** 2026-10-30
**Status:** Accepted
**Deciders:** Wayfinder Map #6

---

## Context

Pool swaps must generate summaries for narrative continuity, but summaries themselves consume tokens and risk leaking evicted content. A balance is needed between informational value and token efficiency.

## Decision

Hand-off summaries are minimal:

- **Format:** 1 sentence maximum
- **Template:** `"Swapped to {POOL_NAME} Pool. {trigger}"`
- **Exclusions:** No evicted content details, no token counts, no file lists beyond trigger

**Examples:**
- ✅ `"Swapped to Testing Pool. Modified auth.ts and db.ts"`
- ✅ `"Swapped to Execution Pool. File read: user-service.ts"`
- ✅ `"Swapped to Planning Pool. Task switch"`
- ❌ `"Swapped to Testing Pool. Evicted 15 messages from Execution Pool containing discussion about user authentication flow..."`

## Implementation

`SummaryGenerator` enforces these constraints via `validateSummary()`:

1. Checks for 1 sentence maximum (period/exclamation/question followed by space or end-of-string)
2. Verifies format: must start with `"Swapped to"` and contain `"Pool."`
3. Rejects prohibited content: `"evicted"`, `"token count"`, `"tokens"`

## Consequences

- Maintains narrative continuity with minimal token cost
- Prevents accidental leakage of evicted context
- Less detailed history for debugging
- Summaries are appended to the target pool as system messages
